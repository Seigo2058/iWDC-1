# アレルギー選択画面 要件定義書

## 1. 背景・目的

ユーザーが自分の食物アレルギーをアプリに登録できるようにする。登録した内容はブラウザの Local Storage に保存し、サーバーやアカウントには送信しない。

現時点のスコープは「**アレルギー情報を集めて保存する**」ところまでで、保存した情報を使って実際に警告を出す機能（6章参照）は含まない。

## 2. アプリ内の位置づけ

| 項目 | 内容 |
| --- | --- |
| 表示タイミング | 撮影フロー（`ConfirmStep`）で「確定する」を押した直後、AI解析（`submitPhoto()`）を呼び出す**前**。ただし**初回のみ**（3.1参照） |
| もう一つの入口 | ホーム画面の「アレルギー設定」ボタンから、いつでも編集できる |
| 保存先 | ブラウザの Local Storage のみ（サーバー送信なし） |

## 3. 画面仕様

### 3.1 表示条件（初回のみ表示）

| 状況 | 動作 |
| --- | --- |
| Local Storageにアレルギー設定が**保存されていない**（初回） | `ConfirmStep`で「確定する」を押すと、AI解析の前にアレルギー選択画面を挟む |
| Local Storageに**保存済み**（2回目以降） | アレルギー選択画面を経由せず、そのままAI解析へ進む |
| ホーム画面から開いた場合 | いつでも、現在の保存内容を初期選択状態として編集できる |

```
【初回の撮影】
確認画面 →（確定を押す）→ [アレルギー選択画面] → AI解析へ
                              ↑
                        保存 or スキップ

【2回目以降の撮影】
確認画面 →（確定を押す）→ AI解析へ（アレルギー選択画面は出ない）

【ホーム画面】
「アレルギー設定」ボタン → アレルギー選択画面（編集モード、保存済みの内容が初期選択）
```

「スキップ」と「何も選択せず保存」は、挙動としては同じ扱いにする（どちらも「設定済み・アレルギーなし」として Local Storage に保存し、以後この画面を出さない）。「本当に何も無いのか」「答えたくないから飛ばしたのか」を区別する要件は無いため、実装を単純にするための割り切りとして明記する。

### 3.2 画面要素

- アレルギー品目のチェックボックス一覧。**カテゴリ別にグルーピングして表示する**（4章）
- 主要アクション
  - **保存して次へ**: 選択内容を保存し、次の画面（初回はAI解析、編集時はホーム）へ進む
  - **スキップ**（初回表示時のみ）: 何も選択せずに「設定済み・アレルギーなし」として保存し、AI解析へ進む
- 編集モード（ホーム経由）では「スキップ」ボタンは不要で、「保存」ボタンのみでよい

### 3.3 データの保存形式

- Local Storageの1キーに、選択したアレルギーの**英語ID（slug）の配列**をJSON文字列として保存する（例: `["shrimp","egg","milk"]`）。
- 表示言語（en/ja/th）に関わらず、保存するのは常にこの英語IDの配列。画面表示のたびに、現在の表示言語のラベルに変換する。
- **キーが存在するかどうか**で「初回かどうか」を判定する（3.1）。存在すれば配列が空でも「設定済み」として扱う。
- サーバーには送信しない。将来的にAIの解析結果と突き合わせる場合も、この英語IDをそのまま使う想定（6章）。

## 5. 決定事項の記録

前版の確認事項はすべて回答済み。決定内容は上記に反映済みで、この章は経緯の記録として残す。

1. 「Apple(りんご)」の重複 → 問題なし。重複を1つにまとめ、代わりに `Soy` を追加して20項目に。
2. タイ語訳 → 確認済み（3章・4章のまま確定）。
3. AI側（`food_items.allergens`）の用語との不一致 → **本リストに準拠する**ことで統一。これに伴い、動作確認用に投入済みのサンプルデータの修正が必要（8章）。
4. カテゴリ分け・件数上限 → **カテゴリ別に表示する**。件数上限は特に設けない。カテゴリ構成は4章の提案どおりとする。

## 6. 今回のスコープ外（今後の検討事項）

- **AIの解析結果との突き合わせ**: `ResultStep`は既に、識別した料理に含まれるアレルギー物質（`FoodData.allergens`）を表示する機能を持っている（`connect-aisystem.md`参照）。ここにユーザーが設定したアレルギー（本ドキュメント）を突き合わせて、「⚠️ この料理には設定したアレルギー品目が含まれています」のような警告を出すことは自然な拡張だが、今回の要件には含まれていない。
- 複数端末間での設定の同期（Local Storageのみのため、端末・ブラウザが変わると設定は引き継がれない）
- アレルギーの重症度（軽度/重度など）の区別
- 「その他」自由入力欄

## 7. 実装方針（案）

- 選択UI自体は共通のコンポーネントとして作り、次の2箇所から使う。
  - 撮影フロー内の新しいステップ（`useCaptureStore`の`step`に追加。`confirm`の後、AI解析実行前に挟む）
  - ホーム画面からの編集用の独立したページ（`/[lang]/allergies` を想定）
- Local Storageの読み書きと、20品目・カテゴリの定義（id・カテゴリ・英語名）をまとめた共通モジュールを1箇所に置き、両方の画面から参照する。
- `ConfirmStep`の「確定する」処理は、AI解析を呼び出す前に「アレルギー設定が保存済みかどうか」を確認し、未設定なら先にアレルギー選択画面へ遷移するよう変更する。
