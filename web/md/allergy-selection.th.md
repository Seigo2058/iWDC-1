# เอกสารข้อกำหนด: หน้าจอเลือกอาการแพ้อาหาร

> เอกสารนี้แปลจากต้นฉบับภาษาญี่ปุ่น `allergy-selection.md` หากเนื้อหาไม่ตรงกัน ให้ถือต้นฉบับภาษาญี่ปุ่นเป็นหลัก

## 1. ความเป็นมาและวัตถุประสงค์

ให้ผู้ใช้สามารถลงทะเบียนอาการแพ้อาหารของตนเองในแอปได้ ข้อมูลที่ลงทะเบียนจะบันทึกไว้ใน Local Storage ของเบราว์เซอร์ และจะไม่ส่งไปยังเซิร์ฟเวอร์หรือบัญชีผู้ใช้

ขอบเขตในขณะนี้ครอบคลุมถึง "**การรวบรวมและบันทึกข้อมูลอาการแพ้**" เท่านั้น ไม่รวมฟังก์ชันที่นำข้อมูลที่บันทึกไว้ไปใช้แจ้งเตือนจริง (ดูบทที่ 6)

## 2. ตำแหน่งภายในแอป

| หัวข้อ | รายละเอียด |
| --- | --- |
| จังหวะที่แสดง | ทันทีหลังจากกด "ยืนยันรูปภาพ" ในขั้นตอนถ่ายภาพ (`ConfirmStep`) และ**ก่อน**เรียกการวิเคราะห์ด้วย AI (`submitPhoto()`) โดยแสดง**เฉพาะครั้งแรกเท่านั้น** (ดู 3.1) |
| ทางเข้าอีกทางหนึ่ง | แก้ไขได้ทุกเมื่อจากปุ่ม "ตั้งค่าอาการแพ้อาหาร" ในหน้าหลัก |
| ที่บันทึกข้อมูล | Local Storage ของเบราว์เซอร์เท่านั้น (ไม่ส่งไปยังเซิร์ฟเวอร์) |

## 3. ข้อกำหนดหน้าจอ

### 3.1 เงื่อนไขการแสดง (แสดงเฉพาะครั้งแรก)

| สถานการณ์ | การทำงาน |
| --- | --- |
| **ยังไม่มี**การตั้งค่าอาการแพ้ใน Local Storage (ครั้งแรก) | เมื่อกด "ยืนยันรูปภาพ" ใน `ConfirmStep` จะแทรกหน้าจอเลือกอาการแพ้อาหารก่อนการวิเคราะห์ด้วย AI |
| **บันทึกไว้แล้ว**ใน Local Storage (ครั้งที่ 2 เป็นต้นไป) | ไปยังการวิเคราะห์ด้วย AI ทันทีโดยไม่ผ่านหน้าจอเลือกอาการแพ้อาหาร |
| เปิดจากหน้าหลัก | แก้ไขได้ทุกเมื่อ โดยใช้ข้อมูลที่บันทึกไว้ในปัจจุบันเป็นค่าที่เลือกไว้เริ่มต้น |

```
【การถ่ายภาพครั้งแรก】
หน้ายืนยันรูปภาพ →(กดยืนยัน)→ [หน้าจอเลือกอาการแพ้อาหาร] → ไปยังการวิเคราะห์ด้วย AI
                                        ↑
                                  บันทึก หรือ ข้าม

【การถ่ายภาพครั้งที่ 2 เป็นต้นไป】
หน้ายืนยันรูปภาพ →(กดยืนยัน)→ ไปยังการวิเคราะห์ด้วย AI (ไม่แสดงหน้าจอเลือกอาการแพ้อาหาร)

【หน้าหลัก】
ปุ่ม "ตั้งค่าอาการแพ้อาหาร" → หน้าจอเลือกอาการแพ้อาหาร (โหมดแก้ไข ใช้ข้อมูลที่บันทึกไว้เป็นค่าเริ่มต้น)
```

"ข้าม" และ "บันทึกโดยไม่เลือกอะไรเลย" ให้ถือว่ามีการทำงานเหมือนกัน (ทั้งสองแบบจะบันทึกใน Local Storage ว่า "ตั้งค่าแล้ว・ไม่มีอาการแพ้" และจะไม่แสดงหน้าจอนี้อีก) เนื่องจากไม่มีข้อกำหนดให้แยกแยะระหว่าง "ไม่มีอาการแพ้จริง ๆ" กับ "ไม่อยากตอบจึงข้าม" จึงระบุไว้อย่างชัดเจนว่าเป็นการตัดสินใจเพื่อให้การพัฒนาเรียบง่าย

### 3.2 องค์ประกอบของหน้าจอ

- รายการช่องทำเครื่องหมาย (checkbox) ของรายการอาการแพ้ **แสดงโดยจัดกลุ่มตามหมวดหมู่** (บทที่ 4)
- การทำงานหลัก
  - **บันทึกและดำเนินการต่อ**: บันทึกรายการที่เลือก แล้วไปยังหน้าจอถัดไป (ครั้งแรกไปยังการวิเคราะห์ด้วย AI, ในโหมดแก้ไขกลับไปหน้าหลัก)
  - **ข้าม** (เฉพาะเมื่อแสดงครั้งแรก): บันทึกเป็น "ตั้งค่าแล้ว・ไม่มีอาการแพ้" โดยไม่เลือกอะไรเลย แล้วไปยังการวิเคราะห์ด้วย AI
- ในโหมดแก้ไข (เข้าจากหน้าหลัก) ไม่จำเป็นต้องมีปุ่ม "ข้าม" มีเพียงปุ่ม "บันทึก" ก็เพียงพอ

### 3.3 รูปแบบการบันทึกข้อมูล

- บันทึก**อาร์เรย์ของ ID ภาษาอังกฤษ (slug)** ของอาการแพ้ที่เลือก เป็นสตริง JSON ใน Local Storage คีย์เดียว (ตัวอย่าง: `["shrimp","egg","milk"]`)
- ไม่ว่าจะแสดงผลเป็นภาษาใด (en/ja/th) สิ่งที่บันทึกจะเป็นอาร์เรย์ของ ID ภาษาอังกฤษนี้เสมอ และจะแปลงเป็นป้ายชื่อตามภาษาที่แสดงอยู่ทุกครั้งที่แสดงผลบนหน้าจอ
- ตัดสินว่า "เป็นครั้งแรกหรือไม่" จาก**การมีอยู่ของคีย์** (3.1) หากมีคีย์อยู่ แม้อาร์เรย์จะว่างก็ถือว่า "ตั้งค่าแล้ว"
- ไม่ส่งไปยังเซิร์ฟเวอร์ ในอนาคตหากนำไปเปรียบเทียบกับผลการวิเคราะห์ของ AI ก็คาดว่าจะใช้ ID ภาษาอังกฤษนี้โดยตรง (บทที่ 6)

## 4. รายการอาการแพ้ (ยืนยันแล้ว・แบ่งหมวดหมู่)

## 5. บันทึกการตัดสินใจ

คำถามที่ต้องยืนยันในฉบับก่อนหน้าได้รับคำตอบครบแล้ว เนื้อหาที่ตัดสินใจได้สะท้อนไว้ข้างต้นแล้ว บทนี้เก็บไว้เป็นบันทึกความเป็นมา

1. "Apple (แอปเปิล)" ซ้ำกัน → ไม่มีปัญหา รวมรายการที่ซ้ำให้เหลือรายการเดียว และเพิ่ม `Soy` แทน รวมเป็น 20 รายการ
2. คำแปลภาษาไทย → ตรวจสอบแล้ว (ยืนยันตามบทที่ 3 และ 4)
3. คำศัพท์ไม่ตรงกับฝั่ง AI (`food_items.allergens`) → ปรับให้ตรงกันโดย**ยึดตามรายการนี้** ส่งผลให้ต้องแก้ไขข้อมูลตัวอย่างที่ใส่ไว้เพื่อทดสอบการทำงาน (บทที่ 8)
4. การแบ่งหมวดหมู่・จำนวนรายการสูงสุด → **แสดงแยกตามหมวดหมู่** ไม่กำหนดจำนวนสูงสุด โครงสร้างหมวดหมู่เป็นไปตามข้อเสนอในบทที่ 4

## 6. นอกขอบเขตในครั้งนี้ (ประเด็นที่จะพิจารณาในอนาคต)

- **การเปรียบเทียบกับผลการวิเคราะห์ของ AI**: `ResultStep` มีฟังก์ชันแสดงสารก่อภูมิแพ้ที่อยู่ในอาหารที่ระบุได้ (`FoodData.allergens`) อยู่แล้ว (ดู `connect-aisystem.md`) การนำอาการแพ้ที่ผู้ใช้ตั้งค่าไว้ (เอกสารนี้) มาเปรียบเทียบ แล้วแสดงคำเตือน เช่น "⚠️ อาหารนี้มีรายการที่คุณแพ้ตามที่ตั้งค่าไว้" เป็นการต่อยอดที่เป็นธรรมชาติ แต่ไม่รวมอยู่ในข้อกำหนดครั้งนี้
- การซิงก์การตั้งค่าระหว่างหลายอุปกรณ์ (เนื่องจากใช้ Local Storage เท่านั้น หากเปลี่ยนอุปกรณ์หรือเบราว์เซอร์ การตั้งค่าจะไม่ถูกย้ายไปด้วย)
- การแยกระดับความรุนแรงของอาการแพ้ (เล็กน้อย/รุนแรง ฯลฯ)
- ช่องกรอกข้อความอิสระ "อื่นๆ"

## 7. แนวทางการพัฒนา (ร่าง)

- สร้าง UI สำหรับเลือกเป็นคอมโพเนนต์ที่ใช้ร่วมกัน และเรียกใช้จาก 2 จุดต่อไปนี้
  - ขั้นตอนใหม่ในขั้นตอนถ่ายภาพ (เพิ่มใน `step` ของ `useCaptureStore` แทรกหลัง `confirm` และก่อนเรียกการวิเคราะห์ด้วย AI)
  - หน้าแยกสำหรับแก้ไขจากหน้าหลัก (คาดว่าเป็น `/[lang]/allergies`)
- รวมการอ่าน/เขียน Local Storage และนิยามของ 20 รายการ・หมวดหมู่ (id・หมวดหมู่・ชื่อภาษาอังกฤษ) ไว้ในโมดูลกลางที่เดียว และให้ทั้งสองหน้าจออ้างอิงจากที่นั่น
- เปลี่ยนการทำงานของปุ่ม "ยืนยันรูปภาพ" ใน `ConfirmStep` ให้ตรวจสอบก่อนเรียกการวิเคราะห์ด้วย AI ว่า "บันทึกการตั้งค่าอาการแพ้แล้วหรือไม่" หากยังไม่ได้ตั้งค่า ให้ไปยังหน้าจอเลือกอาการแพ้อาหารก่อน

## 8. งานที่ยังไม่ได้พัฒนา (งานแยก)

- การพัฒนาหน้าจอ・คอมโพเนนต์ตามเอกสารนี้
- **แก้ไขข้อมูลตัวอย่างใน `food_items`**: ปัจจุบัน `allergens` ของ Tom Yum Goong เป็น `shellfish` (คำที่ไม่มีในรายการนี้) จึงต้องแก้ไขเป็น `shrimp` (เพื่อให้ใช้คำตรงกับบทที่ 4) ส่วน `egg` / `soy` ของ Pad Krapow ตรงกับรายการนี้อยู่แล้ว จึงไม่ต้องแก้ไข
- "การเปรียบเทียบกับผลการวิเคราะห์・การแสดงคำเตือน" ตามที่ระบุในบทที่ 6
